`git.worktree_create` now copies `.worktreeinclude` files the way reference build `f6010b97` does. With git 2.32 or later it searches only the ignored directories that the manifest opens. So `*.txt` no longer copies `build/a.txt` when git ignores `build/`. A one-segment glob without a leading `/` opens each listed directory whose path starts with the literal prefix of the glob. The prefix ends before the first `*`, `?`, `[` or `\`. A literal name opens a listed directory by any segment unless it starts with `/`. After a leading `/`, one segment matches the first segment of a listed directory as a glob, so `/a?b/` opens `aXb` and not `ab`. `build//a.txt` opens `build`. In a longer pattern, a segment that ends in a lone `\` matches any name. Each batch call costs at most 131 072 bytes on Linux and macOS and 24 576 bytes on Windows. The budget is fitted to the measured batches. The `.claude/` pass now splits its children into calls with the same budget, so a `.claude/` with thousands of children is copied. The scan also applies the measured pattern caps, the dot-directory rules, the batch layout and a fallback above 1 MiB of ignored files. A failed batch or `git check-ignore` call now drops only its own paths. With older git the scan now filters its list through `git check-ignore`. It no longer follows a symlinked manifest, and it no longer leaves an empty directory for a nested repository.
